# 收件邮箱管理验收 v0.1

日期：2026-10-10。范围为现有单管理员后台中的收件人维护、指定地址发送及每日投递衔接。

## 实现结果

- “邮件投递”扩展为“邮件管理”：添加邮箱和备注、编辑、启用／停用、删除、最近投递状态；格式校验和重复地址检查由后端执行。
- 收件人保存到 SQLite 持久卷。手动发送、定时发送和页面统计统一读取数据库，名单变化无需重启服务。
- 日报预览中可勾选收件人；只允许发送已确认且质量检查通过的版本。同版本已成功投递的地址跳过，明确失败保留有限重试，结果未知继续人工核实。
- 定时投递开始时固定当天的收件人 ID 和地址，重试、重启不扩大名单。新增邮箱参加下一次日报，当日可手动补发；停用、删除和地址变更会使尚未发送的旧目标跳过。
- 删除邮箱不删除历史回执。收件人 ID 在 SQLite 中不复用，删除再添加不会意外重新命中旧的定时名单；按版本和邮箱的投递去重仍有效。
- 旧 `EMAIL_RECIPIENTS` 一次性导入、去重，无效地址计数在页面提示。导入标记独立保存，即使清空名单，重启也不会恢复旧配置；已有日投递记录在升级时固定原目标。
- 复用管理员会话与同源写入检查。SMTP 发件账户、密码、发送时间仍由部署环境配置，页面分别显示发件服务状态和启用人数。

## 接口

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/recipients` | 收件人列表、最近投递与旧配置导入提示 |
| `POST /api/recipients` | 新增；字段为 `email`、`note`、`enabled` |
| `PUT /api/recipients/{id}` | 保存邮箱、备注和启用状态 |
| `DELETE /api/recipients/{id}` | 删除收件人，保留历史回执 |
| `POST /api/reports/{id}/send` | 可传 `recipient_ids` 指定收件人；空数组拒绝，省略时兼容发送给全部启用地址 |

所有接口均需要管理员身份。日报“已投递”表示该版本已有成功发送记录，具体哪些地址成功以逐地址回执为准。

- 新增 14 项用例，覆盖权限、格式错误、重复地址、CRUD、持久保存、旧配置只导入一次、指定发送、失败／停用、名单固定、次日纳入新邮箱及历史迁移。
- 本地 Linux Docker 已重建并启动，`/ready=200`。真实浏览器完成新增、编辑、停用／启用、勾选发送和删除，页面无 JavaScript 错误；1440 px 桌面与 390 px 手机界面检查通过，手机无页面横向溢出。
- SMTP 仅连接本地 Mailpit。新增两个测试邮箱，只勾选其中一个发送，Mailpit 新增 **1 封**，未选地址没有投递；重复点击后仍为一封、一次尝试。
- 删除已发送的测试收件人后，历史回执仍可查询。重新添加同一测试地址并重建容器，名单与备注保留；再次发送同版本跳过，Mailpit 新增 **0 封**。
- 验收后已移除临时测试收件人，保留原有配置与投递回执。本轮没有调用付费采集接口，也没有向外部邮箱发信。

## 部署衔接

打开后台“邮件管理”维护收件地址，在“简报”预览页勾选地址发送。服务器仍需配置真实 SMTP 账户、授权码并验收实际收件箱；本地 Mailpit 的成功不代表外部邮箱投递已验收。阿里云连接和一天运行观察仍按原计划推进。

使用步骤见 [简报 MVP](../docs/briefing-mvp.md#邮件配置与发送) 与 [Docker 部署](../docs/deployment.md)。
