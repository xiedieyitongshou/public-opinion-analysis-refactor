# 高分误匹配对照诊断（2026-10-23）

## 范围与方法

针对审核 48（居民用电／怀化班列）与 49（兵马俑／朗道–西格尔问题），只读业务数据，独立加载现有本地 `BAAI/bge-reranker-base` ONNX 量化文件，使用 CPU 单线程推理。绕过业务内存／磁盘分数缓存，不新增采集、不写审核结论、不更改运行中的服务。脚本：`backend/scripts/diagnose_reranker_pairs.py`。

左侧为保存于审核记录的 EventSignal，右侧为对应现存候选的标题和描述。候选分别只有一条原始成员，未发现正文串到其他事件。单次结果与历史批次分数不完全相同，以下均标明对照输入。

## 排除与定位

1. **不是 512-token 截断导致候选丢失**：实际长度含特殊标记分别为 276、253，两侧均完整保留。
2. **不是 fast/slow tokenizer 差异**：两种 tokenizer 的 input IDs 一致，单对分数完全相同。
3. **不是只有缓存里存了错误高分**：绕过缓存仍能复现显著高分。
4. **图片占位符不是主要原因**：删除后第二对仍为 0.990097。
5. **可直接定位到当前模型对输入组织方式的敏感性**：问题标题加长描述作为第一侧时出现高分；只保留标题、交换方向或缩短第一侧后明显下降。长文本不是充分原因（仅描述也会下降），不能简化成“超过某个长度必然出错”。
6. **存在批次相关分数漂移**：两对放在同一批次得 0.967151／0.993229；加入长控制样本后得 0.952703／0.995294。保持同一批成员只改变顺序，结果随对应样本移动且值相同，未见简单的位置错配。固定 padding 到 512 的单对结果为 0.928834／0.992940。批次组成和 padding 影响当前量化推理结果，可让第一对跨过 0.95 阈值。

当前缓存只按模型标识和文本对存分，不包含批次组成；因此会保留首次计算时的分数。它会延续漂移，不能解释绕过缓存仍然高分的主要现象。

## 结论及边界

这是当前本地模型在“问题标题＋长描述作为 query，与另一事件作为 passage”用法下的高分误判，并非两个事件真实相同。BGE 官方把该模型描述为 query–passage 相关性评分模型，而不是对称的同事件概率：[模型说明](https://huggingface.co/BAAI/bge-reranker-base)。本项目将其单方向 sigmoid 分数直接用于事件一致性门槛，存在任务适配与分数稳定性问题。

本机只有量化 ONNX 文件，未进行未量化权重对照，因此不能进一步断言主要缺陷一定来自原始模型、量化或 ONNX 导出中的哪一个。量化相关数值误差是批次漂移的合理怀疑，但尚非已独立证实的根因。

后续应优先验证标题作为短 query、对方正文作为 passage，以及双向评分／标题与正文联合校验；保留正文价值，不把此次结果解释为正文必须全部删除。任何新策略须同时检查真实正例，避免用两个负例过拟合。单对固定形状推理可以减少批次变化，但实测不能独自消除这两例的高分。改变打分方法后应升级缓存命名空间，不能继续使用旧分数。

本次仅诊断，不批量修改历史归并或待审记录。
