# 文档命名与维护

[返回项目首页](../README.md) · [文档导航](../README.md#文档导航) · [更新日志](../CHANGELOG.md)

## 入口与分工

根目录 `README.md` 是唯一总目录，负责说明项目价值、实际能力、架构、技术栈与阅读路径。`docs/` 维护当前行为和操作方法，`reports/` 保存有输入范围、日期或版本的验证证据，`CHANGELOG.md` 记录功能演进。

每篇文档顶部链接回根 README；新增正文时在首页对应章节登记。正文可以直接引用相关文档，但不再另建一套首页或要求读者经多层索引才能看到内容。

## 命名规则

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 当前设计与操作文档 | 英文小写、短横线分词，按稳定主题命名，不带周次、开发日或草稿版本 | `architecture.md`、`product-design.md`、`user-guide.md` |
| 功能验收报告 | 主题＋`acceptance`＋验收版本 | `email-management-acceptance-v0.1.md` |
| 采样、评估与检查报告 | 主题＋用途＋版本；特定日期的运行／检查用 `YYYY-MM-DD` | `source-probe-v0.1.md`、`integration-readiness-2026-09-26.md` |
| 机器产物与冻结用例 | 保留生成器定义的文件名，与对应报告版本一致 | `evaluation-v0.2.json`、`system_cases_v0_3.json` |
| 仓库约定文件 | 保留通用名称 | 根目录 `README.md`、`CHANGELOG.md`、`LICENSE` |

报告版本和用例版本是两条独立序列，关系由[评估指南](evaluation.md#用例版本与报告版本)说明。模型配置标识、机器结果名和样本引用不为统一排版而改写。

## 内容归并

同一主题只维护一份正文：

- 产品模式、展示结构和事件卡片归入[产品设计](product-design.md)，字段契约归入[数据契约](data-contracts.md)。
- 工作流与模块交接归入[系统架构](architecture.md)；匹配升级、模型安装归入[事件匹配](event-matching.md)。
- 微博采集方案归入[数据源](data-sources.md)，官媒议程与补证归入[官媒证据](official-evidence.md)。
- 分类组装归入[热点分类](hotspot-classification.md)，评分和趋势归入[平台热度](platform-heat.md)，评估执行与后续用例说明归入[评估指南](evaluation.md)。
- 来源访问判断归入[探测报告](../reports/source-probe-v0.1.md#访问路径与来源选择)；旧周日志的采集部分归入[验收基线](../reports/crawl-validation-v0.1.md#采集阶段实现记录)，后续进展归入[更新日志](../CHANGELOG.md)。

合并前检查独有结论、适用版本、代码引用和生成器输出；迁移后更新仓库内全部引用，删除旧文件，不保留只有跳转的空壳。已经提交过的旧版本由 Git 历史保存。

## 验证证据与维护检查

不同日期、样本或目的的实测各自保留，不把后来通过的结果回填为旧报告的成绩。早期标签和未采用的实验要注明历史范围；报告中的待办不自动代表当前功能缺口。

修改代码行为时同步对应说明；字段定义链接实际 Schema／模型，避免重复维护完整字段副本。纯文档修改检查本地链接、标题锚点、首页可达性与已删除路径的残留引用；涉及报告生成器的引用调整，还需验证生成出的链接。
