## 问题与方案

2026-10-19 的五轮采集里，“法国市政厅被焚毁 → 法国骚乱”和一组自行车赛事关系分别生成五条待审。原去重键使用 `event_signal_id`，但该字段由 `run_id + source_signal_id` 生成，每轮必然变化。此前只改变 run_id、不改变信号 ID 的测试没有覆盖真实情况。

保留轮次信号 ID 用于追踪，另外计算审核关系身份。关系由来源话题身份、候选目标事件和审核标记组成；明确冲突还包含实体、动作、时间事实。不同目标、新冲突不会自动归为旧关系。

| 来源 | 稳定身份 | 边界 |
| --- | --- | --- |
| 知乎 | 从官方问题／回答链接提取问题 ID | 不同问题仍需另行判断是否属于同一事件 |
| 官媒 | 文章 URL，去除 fragment 和 utm_* 参数，统一参数顺序 | 保留正文身份参数，不按标题归并不同文章 |
| 微博 | 来源标题去除外层 #、规整空白 | 相同候选目标、无新增冲突，且距关系首轮不超过24小时才复用；无可靠时间时只在同轮复用 |
| 无法识别 | 回退原轮次信号 ID | 宁可保留审核，不用泛化标题猜身份 |

## 行为与审计

- 待审关系跨轮只保留一张卡片，追加条目、来源引用、轮次、原信号 ID 和匹配历史，页面显示涉及轮数。
- 已明确合并或拒绝的同关系，在当前无显式冲突时复用结论；忽略只关闭当前审核，不作为永久拒绝。
- 旧重复记录归组到一条主记录，原记录设为 cancelled 并保存 grouped_into_review_id，不删除原始内容。主记录保存 grouped_review_ids。
- 一次审核处理主记录的全部关联条目；不替用户提前确认任何候选。新建事件与正常关联后的事件身份仍走原有链路。
- 新一轮创建审核或处理待审时执行兼容归组；历史已决记录不批量改写。微博采用保守24小时边界，同名事件在该范围内仍可能需要更强事实识别。
