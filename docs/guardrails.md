# Guardrails 与人工复核

[返回项目首页](../README.md) · [事件匹配](event-matching.md) · [MVP 使用指南](user-guide.md)

Guardrails 用于事件归并和发布等关键决策；普通请求失败由超时、预算和降级处理，字段格式由 Schema 校验。当前规则由确定性代码执行，未依赖 LLM 审稿。

## 事件归并保护

[`event_merge.py`](../backend/app/guardrails/event_merge.py)与匹配服务共同检查低置信度、实体／时间冲突、语义高分却冲突、只有 embedding 相似、只有弱社区信号等情况。综合阈值见[事件匹配](event-matching.md#决策与阈值)。

明确冲突不能自动合并；缺少足够依据的关系进入人工队列。被否定的是候选关联，合格的独立热榜事件仍可保留。搜索增强另外受到父话题和自动发现边界约束，不能因未找到父事件自行创建新热点。

独立创建的有效热榜话题不再触发“弱信号必须复核”或“仅 embedding 相似”合并护栏；豁免要求动作是 `create` 且没有关联候选事件。实体／动作缺失标记仍保留，实际合并的弱信号仍需接受检查。低 rerank 拒绝阈值和热榜资格见[事件匹配](event-matching.md#决策与阈值)。

`pass/warn/block` 描述检查严重性；`review_required`、`blocks_auto_analysis`、`blocks_publish` 表示相应动作。一个候选需要复核，不等于整轮采集都必须等待人工。

## 简报质量与发布

规则注册表位于 [`default_rules.py`](../backend/app/guardrails/default_rules.py)，日报服务还执行窗口和引用一致性检查。

| 检查 | 处理 |
| --- | --- |
| 事件无来源引用、引用无可用 URL | 阻断发布 |
| 官媒独立事件被写成公众热议 | 阻断发布 |
| 单社区证据作出未经支撑的确定事实断言 | 阻断发布 |
| audit-only 搜索被用作分类支持 | 阻断发布 |
| 缺少保守语言标记 | 记录警告与复核需求 |
| 重复事件、混用轮次／窗口、非法链接、无同窗口分析 | 阻断发布 |
| 官媒引用缺失、报道时间不符合窗口 | 阻断发布 |
| 整轮没有可用来源 | 阻断正常日报发布 |
| 部分来源失败、存在待确认候选 | 保留有效结果并在正文显示限制 |

原始标题只有明确标记为来源引述且能核对引用时才按引用处理；系统生成的摘要和证据文字仍受检查。规则只覆盖明确列出的风险模式，不应宣传为通用事实核查。

## 人工复核

`candidate_review` 任务包含待关联 Item、候选事件、匹配特征、冲突与建议。后台支持归并、单独建事件、忽略和拒绝，搜索增强仍不能通过普通创建操作绕过发现边界。

只有确认后才关联证据并重算分类和趋势。重算使用原始观测时间，生成更正草稿；已保存版本内容不变。决定已保存但重算失败时，任务保留重试入口。官媒相关性疑难项目前不会自动进入这套事件合并队列。

## 手动确认与自动日报

默认手动流程是预览、质量检查、确认版本，再发送。`DAILY_BRIEFING_ENABLED=true` 时，每日专用任务可以自动确认质量通过的版本；不是所有自动采集草稿都自动发布。

阻断结果不能发送，警告随正文保留。已接纳 E 类的低分类置信度不能与尚未确认的合并候选混为一谈，前者仍可以保守展示。

邮件失败与 SMTP 接收未知属于投递状态问题，不由 Guardrails 猜测结果。未知回执需管理员核实后处理；按版本和收件人的去重继续生效。

## 接口与验证

管理员可通过 `/ops/guardrails/rules`、`/ops/guardrails/violations`、`/ops/human-review/tasks` 查看规则、违规和任务；具体写入契约见 [`api/ops.py`](../backend/app/api/ops.py)。日报质量检查见 [`services/briefing.py`](../backend/app/services/briefing.py)。

验证覆盖规则触发、误合并保护、复核关联与发布阻断；离线用例通过不证明所有真实事件都能正确处理，见[评估指南](evaluation.md)。
