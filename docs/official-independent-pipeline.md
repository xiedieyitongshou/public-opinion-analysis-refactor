# 独立官媒栏目与社区事件补证

[返回首页](../README.md) · [官媒依据](official-evidence.md) · [架构](architecture.md)

## 2026-11-01 调整目的

官媒有两个业务角色：独立展示 F 类新闻，以及为知乎／微博事件提供报道依据。此前官媒与社区材料进入同一事件池，分类阶段又比较事件与官媒池；在 LLM 模式下两处均会调用模型，还可能把没有匹配目标的科普、政策汇总转成人工关系复核。

现在两条链路独立。`EVENT_REASONING_MODE=rules|llm` 切换社区语义后端，官媒 F 类整理和补证均不调用 LLM。

## F 类：独立新闻记录

流程：官媒 RSS → 归一化、保存原文 → 发布时间检查 → `build_official_agenda` → 独立 F 类。

- 采集入池要求报道发布时间可靠、不晚于截止时间且在滚动24小时内；本次运行／自定义简报再按所选窗口检查发布时间。
- 使用报道发布时间，不使用抓取时间或首次上榜时间。重新抓取旧稿不能让它重新入窗。
- 当前入口是 RSS 新闻列表，不是已经核验的官媒热度排行榜，不把 RSS 顺序称为官方热度。
- 使用已有文章身份、规范标题与发布日期确定性去重，保留各媒体的来源引用；不对不同表述进行宽泛语义合并。
- 官媒记录标记 `event_domain=official_agenda`，社区召回排除这些候选。科普、政策汇总也可独立展示，无需通过社区弱信号复核。
- F 类文章来源直接复用，不再让文章与自己或所有官媒文章比较。
- 同一事实可以同时有 F 类新闻与社区事件，通过报道引用关联，分别保留事件身份。

## 社区事件：只增加依据

流程：知乎／微博事件 → 规则生成 query → BM25 检索保存的 RSS → 有界候选相关性检查 → 已接纳引用。

- RSS query 召回字面命中的候选，每源最多 `OFFICIAL_SEARCH_LIMIT` 条，总量受 `OfficialSupportConfig.recall_limit` 约束。
- 命中不直接等于依据。复用规则匹配、具体事件约束、来源、URL、发布时间检查；hybrid／hybrid_rerank 仍可使用本地 embedding／reranker，均无 LLM token。
- RSS 无有效依据且启用 `OFFICIAL_SEARCH_ENABLED` 时，保留有预算、带缓存的官网搜索。关闭该开关只关闭官网请求，不关闭本地 RSS query。
- 补证独立回溯默认7天、可配置1～30天，不要求发布于本次采集窗口；时间不能与具体事件冲突，窗口外引用标为“此前报道”。
- 搜索结果只作证据，不自动加入 F 类，不移动到社区事件。人工审核同样禁止跨事件域归并。
- 官媒依据可以影响 A／B／D 等分类，不增加平台热度，也不改变社区事件身份。

## 两种模式的共同边界

| 部分 | rules | llm |
| --- | --- | --- |
| 官媒 F 类整理 | 确定性规则，0 LLM | 相同，0 LLM |
| 官媒 query 和补证 | 规则／本地语义模型 | 相同，0 LLM |
| 社区抽取、归并、CLI相关性 | 规则后端 | LLM 后端 |
| 热度、趋势、分类与窗口 | 公共业务代码 | 公共业务代码 |

分析 Plan 增加 `build_official_agenda` 阶段，由九步变为十步；首页显示“整理独立官媒新闻”。断点版本更新，旧版完成输出不能跨版本直接复用。

## 历史数据与验证

不自动移动旧的已审核条目或改写旧简报。旧数据库中已混合归并的官媒条目再次进入 F 类路径时，会提示需要重建；应先备份，再在隔离数据库回放或开启独立新一期。

回归覆盖两种模式、官媒弱信号独立保留、报道同时作为 F 类来源和社区依据、无官媒 LLM 调用、重复回放、窗口和简报引用。

具体历史回放、HTML简报、阶段用量与耗时保留在本机私有实验目录，不随代码推送。RSS补证的验证不等于官网搜索覆盖率验证，有限历史样本也不能证明全天运行稳定或归并精度已完全达标。

Docker运行时建议将SQLite数据库与缓存保存在数据卷，实验完成后再导出；Windows共享目录的写入开销可能影响处理速度。任务超时保护保持原配置，不因性能测试而放宽。
