# 官媒全文提取、摘要与匹配

[返回项目首页](../README.md) · [官媒证据规则](official-evidence.md)

## 处理流程

官媒 RSS / 官媒定向搜索 → 读取文章缓存 → 有限额地获取原文 → 提取标题和正文 → 选取与标题相关的原句 → 匹配及摘要展示。

2026-10-23 实现。覆盖中新网、人民网、新华网的已知正文容器，纯 Python HTML 解析，不执行网页脚本。标题须与采集标题存在文字关联，不将登录页、错误页、推荐导航当正文。图片和视频不做 OCR 或转写；站点结构变化时允许回退。

## 全文与摘要

- `content` / `content_text` 保存提取出的正文，最多 100,000 字符，截断时留标记；单个 HTML 响应最多 2 MB。
- 摘要为原文句子摘录，不调用生成式 LLM。按标题字符重合度和事实词／数字选句，最多 3 句、合计 600 字符，恢复原文顺序。每句必须来自保存正文或原有来源描述，保留出处链接。
- 网页脚本、导航以及编辑、监制等尾部信息不作为摘要依据。长句无法放入预算时跳过；找不到适合句子则保留来源描述，不编造摘要。
- 抓取失败、缺正文、标题不符、预算耗尽时回退 RSS 描述或搜索片段，同时记录 `official_article_fallback` 和原因。RSS 成功但正文不可用不等于整个来源采集失败。
- `normalized.official_article` 记录版本、实际 URL、原始描述、全文获取状态、失败原因、缓存命中、页面发布时间原始值、摘要来源和摘录。页面时间不自动覆盖原有 `published_at`，防止将更新时间误当发布时间；原有缺日期限制继续生效。

## 接入位置

RSS 归一化和官方搜索适配器共同调用 `official_article.enrich_official_items`。之后普通归一化、入库和事件抽取继续原流程。搜索原文也保存到 Item；已有同 URL 搜索记录获取到正文后可更新正文及摘要。

匹配输入是标题和精简摘要，不把全文无上限拼进 reranker。新 EventSignal、已有候选事件均可使用官媒摘要；官媒补证的候选文章使用其摘要，目标社区事件使用已接纳来源上下文（知乎描述、微博 CLI 摘录），排除仅供审计和搜索增强条目。简报的官媒报道摘录继续复用同一摘要。

本功能不把官媒摘要标为 CLI 正文，不修改热度公式、合并阈值、发布时间窗口、F 类展示规则，也不会自动重算历史归并。已有高分误判及 CLI 放行范围问题仍见[复核报告](../reports/cli-context-rematch-audit-2026-10-23.md)。文字相关或同篇报道提及多个事件仍可能导致误匹配，摘录不是事实真实性或同事件的证明。

## 配置与资源边界

| 环境变量 | 默认 | 含义 |
| --- | ---: | --- |
| `OFFICIAL_ARTICLE_ENABLED` | true | 开启全文及摘要补强 |
| `OFFICIAL_ARTICLE_MAX_FETCHES` | 5 | 每批 RSS 或单个搜索响应最多尝试的未缓存文章数 |
| `OFFICIAL_ARTICLE_TIMEOUT_SECONDS` | 4 | 每次网络操作的超时上限 |
| `OFFICIAL_ARTICLE_BATCH_SECONDS` | 15 | 每批额外文章抓取的时间预算；网络读取结束时还检查剩余预算 |
| `OFFICIAL_ARTICLE_CACHE_HOURS` | 24 | 成功正文缓存期限；失败缓存 10 分钟 |
| `OFFICIAL_ARTICLE_CACHE_DIR` | 数据库旁的 `official-articles` | 可放在 Docker 数据卷中，重启后继续复用 |

按 URL 和提取器版本缓存，每次使用缓存正文仍重新生成摘要。缓存写入失败不会中断采集，会记录标记。大批文章未处理部分保留来源描述；预算为每批上限，不代表所有文章都会抓到全文。

实际 HTTP（含重定向）计入用量的 `official_article_chinanews`、`official_article_people`、`official_article_xinhua`。代码默认每轮每项上限 8；如果环境自定义 `REQUEST_LIMITS`，需显式加入对应键，否则未配置来源沿用通用上限 3。全任务截止时间和请求预算同样生效。每次跳转均重新验证来源域名，拒绝站外、私有地址、带凭据的 URL，最多 4 次请求，不自动重试失败请求。

示例配置见 `backend/.env.example` 和 `deploy/.env.example`。不需要新的模型、密钥或 Python 依赖。通常直接抓公开文章不产生 CLI 积分或 LLM 费用，但会消耗网站请求和少量带宽、磁盘缓存空间。

## 测试与启用

`backend/tests/test_official_article.py` 覆盖 HTML 正文边界、摘要原句出处、匹配两侧输入、补证输入、简报展示、缓存、错误页面、请求预算、站外重定向和 RSS／搜索集成。普通测试默认关闭真实全文请求，专用测试使用 MockTransport。

实测中新网文章可提取 1,361 字符正文；人民网样本发现空的第一个 h1，修复为使用首个非空标题后提取 162 字符正文；新华网一篇文字报道提取 133 字符正文。图片／视频条目可能仅有短描述，继续回退，不宣称完整抓取了图片或视频里的信息。

服务重新加载新代码后，对后续采集生效。历史记录和已生成简报不自动重写；历史补抓及归并重评需作为单独任务执行，避免静默改变已审核内容。本次不发送邮件。
