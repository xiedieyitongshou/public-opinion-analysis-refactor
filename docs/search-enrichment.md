# 搜索增强边界

[返回项目首页](../README.md) · [数据源](data-sources.md) · [事件匹配](event-matching.md)

搜索增强补充已发现话题的讨论和互动。自动发现模式下，社区热点入口是知乎热榜与微博 RSSHub 热榜；系统不从一个平台热榜自动触发另一个平台搜索。

## 三层约束

| 层次 | 要解决的问题 | 当前行为 |
| --- | --- | --- |
| 采集结果初筛 | 搜索返回的内容是否与目标话题相关？ | 逐条检查，再汇总可用指标；噪声只保留审计 |
| 事件归并 | 通过初筛的结果应属于哪个事件？ | 传递父话题关系，核对身份及事件冲突，未确认关系进入复核 |
| 发现边界 | 没挂上父事件的增强结果能否成为新热点？ | 自动模式下不能独立建热点；热榜种子才是社区发现依据 |

初筛通过只是允许进入后续判断，不等于任何场景下都可以强行合并。父话题关系也不是 trace 装饰字段，它约束证据归属、热度和分类。

## 知乎链路

```text
知乎热榜问题 → 父话题／事件
                     ↑
同平台搜索 → 回答逐条初筛 → 父问题身份与事件约束 → 接纳或复核
```

知乎问题与回答可共享 `zhihu:question:<id>`，是强身份依据。自动归并优先处理热榜，再要求回答找到本轮同平台、同来源的热榜父话题。找不到父话题或存在冲突时，回答留在未关联 Item 和复核队列，不独立建热点。

回答数量不要求等于热榜问题数。判断是否正确，应看父子归属和哪些回答获准贡献指标，而不是简单比较两类条目的数量。

## 微博链路

```text
RSS 话题 → CLI 查询 → 全部返回帖子 → 逐条过滤
                                      ↓
                         已接纳样本指标汇总到 RSS 父条目
                                      ↓
                              父话题进入事件归并
```

查询词和 hashtag 是相关性线索，没有知乎问题 ID 那样的稳定身份含义。当前实现将 CLI 样本嵌在 RSS 父条目中，不为每条帖子生成独立热点信号。

每条帖子先分离目标 hashtag、URL 和可识别署名，再保守检查正文首句的明确冲突，最后用本地 reranker 比较 RSS 标题与正文。目标 hashtag 不再单独保证接纳；其他 hashtag 保留文字。缺失实体不算冲突，历史／对比／疑问表达不执行首句硬冲突判定。这些规则不是完整 NER 或事实推理，主体、地点等无法可靠识别时交由相关性评分或降级。

正文不足 8 个有效字符、模型停用／不可用时标记 `audit_only`；不新增人工任务，也不使用旧关键词规则兜底接纳。实际分数低于 `WEIBO_RELEVANCE_REJECT_BELOW`（默认 0.10）排除，达到 `WEIBO_RELEVANCE_ACCEPT_AT`（默认 0.80）接纳，中间档仅审计。这是独立于事件归并的初始阈值，需继续通过真实样本校准，分数不是同事件概率。模型使用 `hybrid_rerank` 配置、本地已有权重和缓存，不调用付费 LLM；长文本受现有 512 token 截断限制。

可解析的发布时间若被判定为超过 72 小时的历史内容则排除；缺失或不可解析的时间保留质量限制。只有接纳样本用于匹配数量、最新可解析时间和互动汇总。全部未接纳时仍保留 RSS 话题，互动指标为空并标记增强不足；`audit_count` 兼容旧字段，包含不确定和已拒绝样本，逐条 `decision` 区分两者。

查询总命中量无法逐条验证，只存审计字段。CLI 返回了十条但仅四条相关时，热度使用四条的已核验样本指标，不使用十条或总命中量冒充相关讨论规模。

## 初筛判定与审计

[`evaluate_search_enrichment`](../backend/app/services/search_enrichment_filter.py)保留知乎同问题身份和原有文本规则；微博 CLI 分支使用 [`weibo_relevance.py`](../backend/app/services/weibo_relevance.py) 的正文评分。已标记的历史污染等仍优先拒绝，不具备完整垃圾营销检测能力。

| `decision` | 用途 |
| --- | --- |
| `accepted` | 可进入后续事件关联和证据处理，仍受父话题与归并约束 |
| `audit_only` | 相关性不足，仅审计，不贡献分类或热度 |
| `rejected` | 已识别冲突或噪声，拒绝贡献 |

`SearchEnrichmentRelation` 保存父话题／信号 ID、匹配原因、拒绝原因、质量标记、置信度与 `audit_only`。时间接近本身不能证明相关，搜索质量 `unknown` 也不能提高分类置信度。

## 对分类与趋势的影响

同平台“热榜＋搜索”仍是一个平台的证据。未确认候选不增加平台覆盖；官媒搜索属于官方补证，也不增加社区平台数。分类代码保留跨平台搜索证据类型，但自动任务没有为了构造 B 类而跨平台补搜的步骤。

CLI 数量、排序和处理口径进入采样签名，趋势只比较有效且可比的观测。修改覆盖范围后不能直接把旧的三话题／截断样本与新样本计算涨跌。

正文过滤使用 `body-rerank-v2` 采样版本，包含模型运行模式和接纳／拒绝阈值，避免与旧 hashtag 过滤口径直接比较。

2026-10-17 使用 10 月 16 日保存的样本进行了五条真实模型回放（未重新请求微博接口）：两条母子救助同义表达从仅审计变为接纳，得分约 0.996／0.954；挂目标标签的大连天气预报从接纳变为拒绝，得分约 0.000038；两条深圳禁鸣内容不再误报地点冲突，得分约 0.811／0.976，均接纳。这是已知案例的回归证据，不是全量准确率评估；历史数据库没有回填。

旧数据库里已拆分的事件、旧 CLI 汇总和采集缓存没有自动批量回填。同轮回放复用旧响应，不能重新执行当时未做的逐条过滤；历史修正需另行重采或处理旧数据。修复证据见[评估 v0.1](../reports/evaluation-v0.1.md#本轮问题定位)。
