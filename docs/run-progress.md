# 任务进度与本轮用量

[返回项目首页](../README.md)

2026-10-21：主页新增“当前任务状态”，区分排队、采集、数据整理、事件提取与归并、审核整理、热度计算、官媒补证与分类、趋势分析、简报生成／质量检查／保存。阶段直接来自执行中的工具，不估算整体百分比。

知乎热榜、知乎搜索、微博采集、三个官媒 RSS 分别展示等待／运行／完成／失败。微博进一步显示 RSS 获取，以及 CLI 已处理话题数／计划话题数、返回样本数、相关性接纳数与失败话题数。处理完不等于所有话题成功，CLI 部分失败会单独标记。

运行与来源区域新增当前／最近一轮接口明细，按 run_id 汇总已经结束的请求次数、成功失败和累计耗时。微博按已解析条数乘3提供积分估算，不是服务方实际账单，不含启动检查、无法解析的响应等；原有过去24小时用量和额度展示保留。

页面可见时每5秒读取 `/api/run-progress` 与采集任务状态，无重叠轮询，不发起新采集。读取失败显示提示并保留上次结果；任务失败或中断后，未完成模块不会继续显示运行。新接口沿用管理员鉴权。

右上角按钮改为“立即采集一次”，注明默认配置与付费接口；排队、运行或连续采集期间禁用重复启动入口，服务端原有单任务约束仍保留。

进度由执行进程写到数据库同目录的 `progress/`，以 run_id 的 SHA256 命名，临时文件完成后原子替换。它不占用业务数据库写事务，避免模型计算／归并期间进度不可见；数据库中的任务状态仍是最终依据。快照不保存原始正文、CLI授权或邮箱密钥，写入失败仅记录警告，不中断采集。历史任务没有快照时显示已有采集结果，不伪造细分进度；独立新任务不读取旧轮次快照。

本次不改变采集频率、CLI条数和计费策略。连续任务等待下一轮的信息仍看“采集任务”区域，主页任务状态显示当前或最近一轮；已有数据的窗口简报重建仍使用原有任务状态，并非全部细分工具都有进度快照。
