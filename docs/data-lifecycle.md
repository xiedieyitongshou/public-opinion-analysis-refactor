# 数据生命周期与存储

[返回项目首页](../README.md) · [部署与备份](deployment.md) · [数据契约](data-contracts.md)

本章区分已经运行的持久化机制和未来清理设计。当前会按天保留并轮转运行日志，**业务条目、事件、快照和日报尚未按早期草案自动删除或压缩**。

## 当前存储层次

| 层次 | 内容 | 当前用途 |
| --- | --- | --- |
| 来源与条目 | Source、Item、标准字段、原始指标和关系审计 | 溯源、复核与事件关联 |
| 事件与观测 | Event、PlatformScore、EventSnapshot | 稳定事件身份、分平台热度与真实时间线 |
| 分析与运行 | AnalysisRun、AgentTask、AgentToolCall、RequestLog、QuotaSnapshot、JobLease | 轮次回放、任务恢复、用量与失败定位 |
| 人工与质量 | HumanReviewTask、GuardrailViolation | 候选确认、保护规则和更正重算 |
| 日报与邮件 | DailyReport、ReportRevision、DailyBriefingJob、EmailRecipient、DailyEmailAudience、EmailDelivery | 固定版本、收件人管理、按日投递和去重 |
| 文件与缓存 | HTML／JSON／文本归档、JSONL 日志、语义分数缓存 | 导出、运行排查与模型计算复用 |

本地 SQLite 默认 `backend/data/app.db`。Docker 的数据库、日志、日报文件和 CLI 状态分别放在持久卷，模型以只读目录挂载。详细表定义见[数据库模型导航](data-contracts.md#数据库模型导航)。

## 热点窗口不等于数据删除

当前结果根据滚动 24 小时的有效发现证据入选；最后有效证据过期后不再返回该事件，但数据库记录保留。当前离榜也不立即清空当天已存在的分类来源。

`active/cooling/archived/ignored` 等生命周期字段是长期管理入口，不能单凭 `active` 查询充当当前榜单。早期“48 小时转 cooling、7 天归档”等策略尚未变成已运行的清理调度。

审核或重评分使用原始观测时间，不制造新快照时刻；同 `run_id` 回放复用原采集。日报另存固定版本，后续采集、审核和联系人变更不会改写已经保存的内容或删除发送回执。

## 已实现的保留与限额

- 设置 `RUNTIME_LOG_DIR` 后，日志实时追加到 `YYYY-MM-DD/*.jsonl`，默认北京时间分日，`RUNTIME_LOG_RETENTION_DAYS=14`；轮转只清理受控日志目录。
- Docker 标准输出按大小轮转，每服务最多 3 个 10 MB 文件；它与应用按天日志是两套机制。
- 可选 reranker 缓存按模型和精确文本对保存分数，初始化时清理过期记录并限制规模；它不保存业务合并决定。
- 采集请求预算、工作超时和 `SCHEDULER_UNTIL` 限制运行与外部调用，不是数据库清理策略。

日志记录轮次、步骤、耗时和错误，并对已知密钥脱敏，不应记录完整采集正文。数据库和本地原始样本不是可公开报告，应与代码分开管理。

## 后续保留策略草案

早期设计中的下列周期保留为待验证方案，**当前不自动执行**：

| 对象 | 早期建议 | 实施前需要确认 |
| --- | --- | --- |
| 原始 payload | 3 天 | 审核、回放及错误追溯是否仍需原件 |
| 普通 Item | 14 天 | Event、引用、日报与复核的关联是否可安全保留 |
| 高频快照 | 7 天 | 压缩后能否解释趋势和缺测 |
| 日级压缩快照 | 90 天 | 数据结构、聚合口径和验证 |
| 自动草稿 | 7 天 | 已确认版本、更正版本与投递回执不能被误删 |
| 正式日报与轻量事件摘要 | 长期 | 实际存储增长和备份成本 |

这部分需要独立实现清理任务、dry-run、审计和故障恢复。原有 40 GB 容量假设与磁盘告警阈值是设计输入，尚没有长期运行数据证明容量足够；应在一天试运行后先测量增长再决定。

## 备份与更新

当前采用单实例／单 Uvicorn worker。维护时先停止后端任务，再备份 SQLite，防止直接复制到不一致文件；更新镜像复用持久卷。不要用删除卷的方式升级。

具体命令、日志导出和一天试运行审计见[部署指南](deployment.md#备份与更新)。收件名单及发送去重记录也属于需保留的数据。Mode B 若后续加入主题追踪，应另设 TTL 与停止条件，不能默认把每次查询变成永久采集任务。
