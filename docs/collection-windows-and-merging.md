## 启动采集

后台首页“采集任务”支持设置运行时长（1～168 小时，留空表示持续运行）、采集间隔（30～180 分钟）、结束后生成本次运行简报／过去24小时简报／仅保存数据。保留“夜间8小时预设”：立即采集一次，再每小时一次，计划九轮。不能整除时只安排截止时间以内的轮次，到截止时间再结束。持续运行需要主动停止，仍会消耗接口额度。

此入口采集知乎热榜、知乎搜索增强、微博 RSS 和 CLI 增强，以及中新网即时新闻、人民网时政、新华网时政 RSS，复用普通采集的来源配置。官媒定向搜索补证遵循 OFFICIAL_SEARCH_ENABLED，回溯窗口与本期展示分离，见[官媒补证说明](official-evidence.md)；RSS 抓取不使用微博 CLI 额度，但会占用网络和后续分析资源。新增来源从下一轮采集生效，不补写历史轮次。开始前应关闭常规定时采集及自动日报／定时邮件，避免双重调度。微博授权、模型与容器内存检查沿用原流程；启动检查会真实调用一次微博搜索。请求数和消费以实际接口记录为准，不根据预计轮次伪造费用。

关闭网页不会停止采集；电脑不能休眠，Docker 必须持续运行。任务配置、开始时间和轮次保存在数据库中。重启后恢复原计划，漏采记为跳过，不集中补跑；停止会等待正在执行的轮次结束。此入口不自动确认简报或发送邮件。

## 选择简报范围

“根据已有数据生成简报”提供三种范围：

| 范围 | 数据来源 |
| --- | --- |
| 本次运行 | 当前采集任务各轮的真实采集记录；既有事件可以复用，但历史证据不混入 |
| 过去24小时 | 截止时间之前24小时内已有的全部可用采集记录 |
| 自定义 | 选择起止时间，最长七天；没有采集的历史无法补造 |

时间输入按浏览器本地时区转换，界面报告按配置时区展示。只有已接纳关联的证据参与分类。搜索增强不能独立产生热点；本期没有热榜／官媒发现证据的孤立搜索结果不进入正文。官媒依据按发布时间进入所选窗口，重复抓取旧报道不能刷新其时效。

汇总先找真实采集记录，再映射到已接纳的事件，分别生成分类、平台内趋势和引用。内容去重后重复采集的文章仍可使用本轮观测时间作为引用采集时间，不改写文章发布时间。各来源最后一次状态与窗口内失败记录同时保留，不以最后一轮成功掩盖之前失败。

同一份简报固定保存起止时间、来源轮次和采样配置，审核后的更正版沿用这些信息。新窗口生成新简报；同一采集任务的更正版显示在同一个轮次下，入口指向当前版本，历史版本继续保留。

未采集官媒代表没有本次观测，不能表述为官媒没有报道。相同事件在“本次运行”和“过去24小时”中的类别可能不同，因为两种范围接纳的证据不同。

## 审核后的热度与质量检查

选择“单独建事件”时，名称框默认填写候选话题标题，可自行修改。未填写名称时，后端依次使用审核记录标题、事件信号标题和引用标题，不再把事件 ID 当作展示标题。历史简报仍保留生成时的标题，更正现有事件后生成新版本。

审核确认关联后，系统根据保存的原始轮次重建事件观测，同平台同轮次按稳定观测 ID 更新，不把重复快照累加为热度。知乎、微博保持各自量纲，跨平台只比较事件覆盖。重算继承原采样间隔，不再因汇总任务输入为空而让全部趋势变成未知；不足两次可比观测、漏采、采样口径变化仍可能产生未知。

没有当前有效引用的事件从正文排除并提示，不再仅因排除项存在而阻止整份报告。正文缺少引用、非法来源链接、分类与趋势窗口不一致、全部来源不可用、空简报等仍阻止发布。此修改没有取消正文质量检查。

旧的夜间任务没有配置时按8小时／60分钟兼容；审核或手动重新生成会使用新的汇总方式。旧版内容不直接覆盖，管理员可检查更正版后决定是否发布。

## 自动归并规则

跨轮审核重复问题已于2026-10-20改用稳定来源身份修复，轮次信号 ID 保留用于审计。微博复用限制为24小时；忽略不再当作永久拒绝。详见[审核关系身份方案与修改记录](review-relation-identity.md)。下方10月19日验证记录描述修复前的历史现象。

1. 同平台稳定 ID／规范 URL 匹配，且无明确冲突时复用事件。知乎问题链接与该问题的回答链接共享问题 ID；不同问题 ID 不构成强身份匹配，即使标题相似。
2. 明确的主体、动作、地点、日期、型号、章节期数等冲突阻止自动合并；缺少字段不等于冲突。
3. 既有实体和动作支持的高分路径保留。新增不依赖 NER 完整输出的路径：reranker ≥0.95、双方标题至少8个有效字符，并有标题包含、足够文字重合，或文字重合加至少两个相同的多位数字细节；模型不能处于降级状态，也不能有明确冲突。该高分用于最终置信度，避免继续被0.60候选门槛挡住。
4. 多个高置信候选的差距小于0.03时保留人工复核，防止随意选一个。短泛词、高分但文字依据不足、中间分数仍可能送审。低 reranker 分数沿用低于0.10的不关联规则；热榜可独立建事件，搜索增强不可独立建热点。

高分是相关性分数，不是“同一事件的概率”，也不是无条件合并许可。微博 RSS＋CLI 的逐条正文过滤继续使用独立路径，本次没有把事件归并阈值套到样本过滤上。

同一信号与同一目标、相同冲突状态的待审关系跨轮次合并为一条记录，保留涉及的轮次、条目和引用。已有明确人工合并或拒绝结论可在相同关系无新冲突时复用；忽略只关闭当前审核。新冲突仍重新判断，不让历史审核覆盖新证据。

## 验证与限制

2026-10-19 官媒接入验证：连续任务复用普通采集的官媒 RSS 来源，11项调度与窗口回归测试通过，包含官媒事件进入窗口简报并形成 F 类的用例。实际3小时／45分钟任务完成5轮，简报包含知乎22个、微博31个、官媒3个事件。官媒每轮返回60条，但人民网返回旧稿、新华网缺少发布时间；中新网23篇去重报道只有3篇发表于本次窗口内。请求成功不等于来源能提供当前新闻。

本轮仍发现三个待修问题：审核去重依赖每轮变化的事件信号 ID，同一关系仍重复送审；趋势历史尚未充分传入单轮热度子分；部分官媒入口需替换或加强过期状态提示。本次提交仅解决连续采集遗漏官媒 RSS，不表示上述问题已经修复。

回归测试覆盖历史事件隔离、重复采集引用时间、固定窗口重算、可配置轮次、持续运行与停止、旧版入口、高语义分数且缺实体、明确章节冲突、泛词不自动归并、审核关系跨轮去重。真实测试数据在数据库副本中离线重建，不新增采集或邮件投递。

2026-10-18 验证：374 项离线测试通过，修改文件的 Ruff 检查和前端 JavaScript 语法检查通过。测试容器最初缺少评估数据的相对路径，补齐只读路径后相关测试通过。真实夜间数据先在副本验证，再备份原库并通过后台接口生成第21版更正版：本次运行范围内85个已接纳事件，知乎栏目41个、微博44个、官媒0个，质量检查无阻断。人工确认的生活费事件在夜间窗口只采到知乎，微博证据来自之前的轮次，因此本次运行中不应显示为跨平台。这是范围变化，不是丢弃人工审核关系。

原始采集、人工结论和旧简报保留；新语义归并规则用于后续分析，不自动改写已经完成的人工判定。第21版仅为本地草稿，没有确认或邮件投递。随后修复独立建事件的标题默认值，10项人工审核测试通过；将“重阳节”的历史占位标题更正后生成第22版草稿，事件总数仍为85，旧版保留。部分事件仍因观测不足或不可比而没有趋势，不能据此推断热度不变。

标题事实识别仍是保守规则，不是完整 NER；长标题语义相似仍存在误合并风险。需要继续积累人工判定的正反例进行回放，不能仅凭单次测试宣布达到准确率目标。平台趋势“未知”保留真实数据缺口，不能通过补零或虚构历史修饰。
