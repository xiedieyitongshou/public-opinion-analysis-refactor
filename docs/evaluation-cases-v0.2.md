# 三模块评估用例 v0.2

本版把 Day48 的运行器与 Day49 的用例构建、执行和报告合在一起，评估当前已经实现的采集、归一化与事件构建、热度与趋势三个模块，以及它们之间的九步 Tool 编排。结果见 [评估报告](../reports/evaluation-v0.1.md)，逐例预测见 [JSON](../reports/evaluation-v0.1.json)。

## 数据与标签

固定用例集位于 [system_cases_v0_2.json](../backend/app/evaluation/cases/system_cases_v0_2.json)，共 134 条：

| 范围 | 数量 | 内容 |
|---|---:|---|
| 归一化与时间接口 | 20 | 发布时间缺失不补造、采集身份保留、重复归一化、来源引用 |
| 事件匹配 | 48 | 20 对真实不同事件、2 对同问题的真实答案、20 对同 URL 衍生变体、6 对历史标题 |
| 官媒相关性 | 13 | 8 对真实无关证据、4 对同篇文章身份对照、1 个证据池不可用场景 |
| 分类规则 | 8 | A–F、unknown、CLI 失败时的置信度 |
| 热度与排序 | 8 | 平台独立、RSS 顺序语义、搜索低相关排除、同平台同类别排序 |
| 时间与趋势 | 18 | 上升、下降、平稳、断档、离榜、重入、缺测、重复观测、未来数据、评分口径变化 |
| 采集 | 9 | 实际 Collector 解析、完整/不完整榜单、空榜、缺失日期、XML 错误、超时和 HTTP 错误 |
| 完整编排 | 10 | 官媒误匹配、旧新闻、同问题搜索、两轮趋势、跨平台合并、幂等重跑、故障、弱信号、空数据 |

公共语料保留 2026-09-28 实采中的 24 条主采集记录和 2 条知乎搜索答案的最小摘录；核心候选主题从中选择 20 个，覆盖社区热点、弱标题、当日官媒、旧日期和缺失日期。保留标题、去除跟踪参数的 URL、时间、源信息、指标与采集哈希，省略正文、用户资料、完整原始响应和凭据。采集哈希用于追溯原件，并非声称摘录与原件内容完全相同。

所有新增语义标签都是**助手整理、待人工复核**；历史 6 对沿用 Day27 的 `same_event` 标签，但只重放标题及占位 URL，不重放原始搜索响应。业务规则的期望在生成脚本中独立列出，运行器不能用 expected 构造分类输入，也不会根据当前预测更新标签。

### 数据类型与分区

- `real_excerpt`：实际采集内容的摘录；不是完整原始响应。
- `legacy_title_pair`：既有 Day27 标题对标签，在本轮规则抽取与匹配中重新执行。
- `derived`：从真实条目构造的空白变体、重复采集、人工时间线或证据身份对照。
- `synthetic`：明确列出的规则边界、分类证据组合和故障注入场景。

20 个核心主题按事件组分为 dev 14 / holdout 6。引用同一事件的答案、变体和链路用例必须保持同一分区；加载器检查跨分区泄漏、重复用例 ID、缺失语料引用及漏列事件组。历史标题对和合成规则场景列为 regression。

本轮没有调参，holdout 只是预留分区，标签与分区均由助手整理，不声称人工盲评。真实正例只有同一问题的两个答案，holdout 正例都是同 URL 变体。混合 Precision/Recall/F1 仅用于排查，必须同时查看来源分组；20 个候选主题不能视为 20 个具有完整独立事件标注的统计样本。

## 执行方式

在仓库根目录的 PowerShell 中运行：

```powershell
Set-Location backend
& ../.venv/Scripts/python.exe -B -m app.evaluation --output-dir ../reports
```

不需要 API key、Docker、在线 LLM 或数据库服务。所有用例使用固定的 2026-09-28 业务时间窗口，网络连接受到运行器阻断。完整链路创建独立的 SQLite 内存库，复用正式 `HotspotAnalysisAgent` 的九步工具，仅替换 `fetch_source_items` 的返回值。结束后释放内存库；不会向现有业务数据库写入样本。

单条真实摘录回放默认不声明完整榜单；仅在明确构造的两轮趋势用例中通过 `complete=true` 声明完整的模拟观测。原始整轮回放保留原始元数据。未执行重试的场景中 `idempotent=null`，不把未进行的检查写成通过。

可单独运行预留分区或指定用例，建议输出到临时目录，避免覆盖完整基线：

```powershell
& ../.venv/Scripts/python.exe -m app.evaluation --split holdout --output-dir $env:TEMP/poa-holdout
& ../.venv/Scripts/python.exe -m app.evaluation --case-ids workflow-search-same-question --output-dir $env:TEMP/poa-case
```

有本地原件时可增加整轮回放。下面是本次报告的完整命令；克隆仓库后仅执行默认命令即可复现公共用例，无须私有原件。

```powershell
& ../.venv/Scripts/python.exe -B -m app.evaluation --output-dir ../reports --raw-replay ../notes/source-probe-raw/live-analysis-20260928-112421/collection.json
```

原始回放保留采集轮次和观测元数据，只报告结构性输出，不加入语义准确率分母。其原件 SHA-256 进入报告，不提交原件。机器结果包含数据哈希、app 源码哈希和 Git 基线；运行时间、数据库生成 ID 等不要求逐字节相等。

退出码为 0（全部通过）、1（业务预期不符）、2（执行错误或无效输入）。本轮报告中存在业务预期不符，返回 1 是评估结论，不是运行器崩溃。用例异常单独记为 error，不能算作正确负例；空选择和不存在的 ID 不能输出“100%”。

## Agent Tool

原有 `run_evaluation_suite` 占位已实现。示例输入：

```json
{"case_ids": ["workflow-idempotent"], "split": "dev"}
```

省略筛选即运行全部固定用例。Tool 在独立子进程运行评估，避免网络阻断和样本状态影响宿主中的其他任务；仅在调用方提供数据库 Session 时保存 `EvaluationRun` 的摘要、指标与时间。完整逐例报告也在 Tool 输出中返回。该工具仍属于现有 Registry，未加入每轮热点分析的九步业务链路。

## 指标口径与边界

- 自动合并：`merge` 且无复核/自动分析阻断才算预测正例。正例转人工计自动召回 FN，复核率另列；负例未自动合并计 TN，不代表创建结果一定正确。当前每例仅提供一个已知候选，不测大规模候选召回和聚类。
- 官媒：supported 与 weak_supported 均作为“有支持”；无关文章被支持计 FP。四个同篇文章正例是身份对照，不能解释为一般语义匹配召回率。
- 分类：类别正确率与置信度检查分开；在给定正确证据组合的合成用例上通过，不代表上游证据也正确。
- 趋势：按预期 rising/stable/cooling/unknown 判断，unknown 单列；持续时间 MAE 只使用两边都有数值的样例，同时报告缺失预测数量。
- 排序：使用正式展示排序入口，限制同平台、同类别；不以跨平台总分比较热度。
- Tool：返回合法结果与业务成功分开计数；例如采集超时可以被 Tool 正常返回，但任务状态是 failed。
- 采集稳定性：本轮只能验证离线解析和故障处理。既有 1 轮实采及 CLI 恢复复测不足以估计长期可用率；没有新增在线请求，也没有评价额度消耗、持续限流、并发吞吐或真实连续趋势。
- 日报、embedding、LLM 动态规划不在本次启用路径；不给未执行的能力生成成绩。

## 维护与人工复核

新增样例时应先记录来源、事件边界、预期和依据，再执行系统；不要因当前实现不通过而把标签改成预测结果。修复后对同一版本用例运行，保留报告作对照。新增或更正语义标签需记录理由并升级用例版本。

[构建脚本](../backend/scripts/build_evaluation_cases_v02.py)用于从本地原件重新生成冻结文件，不是正常执行评估的依赖。它不读取评估预测。构建过程中修正了一个夹具口径：微博 RSS 使用实际 `topic_discovery_signal`，按照已有 Day44 契约允许 `primary_platform_rank` 存放列表顺序，同时检查 raw_metrics 明确标为 `list_position`；这与“不能冒充官方热值”的边界一致。

旧新闻入池的 `event_count=0` 是拟定产品验收要求，尚待确认允许的历史证据用途。本轮保留其不符合结果并单独说明，不把该要求描述为已经确认的业务契约。建议人工优先复核该条、8 对官媒负例及历史标题对，再补充自然跨平台正例与真实 A/B/D 类样本。

本次配套代码验证：`python -B -m pytest -q` 共 210 项通过，包含 14 项新增运行器测试；2 条警告来自既有依赖弃用提示。`python -B -m ruff check app tests scripts/build_evaluation_cases_v02.py` 通过。运行器测试覆盖标签独立性、空分母、错误分离、网络阻断、分区泄漏检查、CLI 退出码及 Tool 结果持久化；它们的通过与业务评估中 16 条预期不符是两种不同结果。
