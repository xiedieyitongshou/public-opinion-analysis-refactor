# 邮箱配置与日报投递

[返回项目首页](../README.md) · [Docker 部署](deployment.md) · [后台使用指南](user-guide.md) · [邮箱管理验收](../reports/email-management-acceptance-v0.1.md)

本项目通过 SMTP 将已确认的日报逐个发送给启用的收件邮箱。一封邮件同时包含 HTML 和纯文本正文。发件服务在“邮件设置”页面配置，收件人在“收件人管理”页面维护；添加收件人不会自动配置发件账号，也不会立即发送日报。

## 发送前需要准备什么

| 条件 | 需要完成的事情 |
| --- | --- |
| 可用的发件账号 | 在邮箱服务商处开通 SMTP，取得服务器地址、端口、账号和授权码或 SMTP 密码；不能默认使用网页登录密码 |
| 兼容的认证方式 | 当前使用 SMTP 用户名／密码认证，支持 SSL 和 STARTTLS；尚未实现 OAuth2 登录，只支持 OAuth2 的账号不能直接接入 |
| 合法的发件地址 | `EMAIL_FROM` 填纯邮箱地址，通常与认证账号一致；使用其他地址需服务商允许，不能随意伪造发件人 |
| 服务器网络 | 部署服务器能够解析并连接 SMTP 主机及指定端口；检查出站网络、防火墙和服务商限制，无需为本项目开放公网入站 SMTP 端口 |
| 启用的收件人 | 登录后台“收件人管理”，添加并启用至少一个真实收件邮箱 |
| 可发布的日报 | 已生成且通过质量检查，并经人工确认或自动日报流程确认的版本；草稿和质量阻断版本不能发送 |

费用由所选邮件服务商决定，项目本身不额外收取邮件发送费用。少量试运行可先确认现有普通邮箱是否提供免费的 SMTP 权限及额度；扩大收件人数前再核对发送频率、配额和计费规则。使用普通邮箱不要求为本项目购买域名；如果选择自有域名发信，需按服务商要求完成域名验证和 SPF／DKIM 等配置。

## 推荐方式：在管理页面配置

先部署应用并在运行环境中设置一次 `EMAIL_SETTINGS_KEY`。这是独立的 Fernet 加密密钥，不是 SMTP 授权码，也不是后台登录口令。安装项目依赖后可在自己的终端生成：

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

将输出填入实际环境文件的 `EMAIL_SETTINGS_KEY`，重新创建容器使之加载。备份数据库时也要单独安全备份此密钥；不要提交 Git 或随意更换。丢失密钥后旧授权码无法解密，需要恢复原密钥或在页面重新填写授权码。

登录后台打开“邮件设置”，填写发件服务、定时开关、触发时间、时区和重试参数，然后保存。页面显示配置来自环境还是数据库，以及授权码是否已设置。授权码不回显；输入框留空保留原值，勾选清除则删除原值。首次保存时，环境中已有的授权码也会加密迁入数据库，需要有效加密密钥。

保存后，点击“检查连接与认证”只验证已保存的配置，不发送邮件。需要验证真实投递时，填写测试邮箱并主动点击“发送测试邮件”；该操作会发送一封固定测试正文，不需要日报，也不会新增收件人。结果显示在页面，测试邮件不进入日报的版本投递回执。SMTP 接受后仍需核对真实收件箱；结果未知时先核实，不要反复点击。

数据库保存的是一整份邮件配置。保存后 SMTP、调度及日报时区以数据库为准，环境变量不再逐字段补齐；停用或清空不会恢复旧环境值。后续发送批次和调度检查使用新配置，无需重启；已开始的发送批次使用同一份配置快照。当前没有恢复环境配置按钮。

邮件设置接口均要求管理员身份：`GET /api/email-settings` 查看脱敏配置，`PUT /api/email-settings` 保存完整配置，`POST /api/email-settings/check` 检查连接，`POST /api/email-settings/test` 向指定地址发测试邮件。普通用户不应获得管理后台权限。

## 环境配置与首次兜底

本地 Python 运行使用 `backend/.env`；默认 Docker 部署使用 `deploy/.env`，模板见 [deploy/.env.example](../deploy/.env.example)。若设置了 `APP_ENV_FILE`，应修改它指定的文件。不要将实际授权码或密码提交到 Git。

尚未通过页面保存配置时，下面是首次调试的配置片段，**合并到现有环境文件中，不要覆盖其中的来源凭据、后台口令等配置**。示例地址和凭据必须替换为服务商提供的真实值：

```dotenv
EMAIL_FROM="briefing@example.com"
SMTP_HOST="smtp.example.com"
SMTP_PORT=465
SMTP_SECURITY=ssl
SMTP_USERNAME="briefing@example.com"
SMTP_PASSWORD="替换为邮箱授权码或SMTP专用密码"
SMTP_TIMEOUT_SECONDS=20
EMAIL_MAX_ATTEMPTS=3

# 收件人优先在后台添加
EMAIL_RECIPIENTS='[]'

# 先手动验证真实收件，再开启自动流程
DAILY_BRIEFING_ENABLED=false
EMAIL_SCHEDULE_ENABLED=false
EMAIL_SEND_TIME=08:00
BRIEFING_TIMEZONE=Asia/Shanghai
```

| 配置 | 作用与填写要求 |
| --- | --- |
| `SMTP_HOST` | SMTP 主机名，不带 `https://` |
| `SMTP_PORT` / `SMTP_SECURITY` | 按服务商要求配对；常见为 `465`＋`ssl` 或 `587`＋`starttls`，不能只改端口 |
| `SMTP_USERNAME` / `SMTP_PASSWORD` | 认证账号及授权码或 SMTP 专用密码；普通邮箱通常要求完整邮箱地址作为账号 |
| `EMAIL_FROM` | 收件人看到的发件地址，当前填纯邮箱地址，不填“姓名 <邮箱>” |
| `SMTP_TIMEOUT_SECONDS` | 网络操作超时秒数，默认 20，可设 1～60；不是整个每日任务的时限 |
| `EMAIL_MAX_ATTEMPTS` | 单个版本对单个收件人的最多发送尝试次数，默认 3，可设 1～5；不是失败后额外重试 3 次 |
| `EMAIL_RECIPIENTS` | 可选初始名单，JSON 数组，例如 `'["reader@example.com"]'`；只初始化导入一次 |
| `EMAIL_SEND_TIME` / `BRIEFING_TIMEZONE` | 每日触发时间及其时区，例如北京时间 `08:00` |

`plain` 仅用于可信的隔离测试环境，例如 Mailpit；真实外部邮箱使用服务商支持的加密连接。配置定义见 [Settings](../backend/app/core/config.py)，认证与投递行为见 [邮件发送实现](../backend/app/services/briefing_email.py)。

页面保存的配置无需重启；以下操作仅用于部署环境变更。修改环境文件后，本地 Python 服务需要重启。Docker 在仓库根目录执行以下命令重新创建后端容器，使环境变量更新生效；仅执行 `docker compose restart` 不会重新载入环境文件：

```bash
docker compose up -d --no-deps --force-recreate backend
docker compose ps
```

命令需沿用部署时的 Compose 项目名、配置文件和 `APP_ENV_FILE` 设置。真实发送不要叠加 `compose.test.yml`：它会覆盖 SMTP 配置并把邮件投递到 Mailpit。

## 收件人管理与首次发送

1. 登录后台，在“收件人管理”添加一个自己可检查的收件邮箱并启用。该页面支持备注、编辑、启用／停用和删除，保存即时生效，无需重启。
2. 完成一次采集与日报生成，在日报页面检查过去 24 小时的内容、来源警告和质量检查结果。
3. 点击“确认此版本”，通过发布检查后勾选测试收件人手动发送。
4. 查看逐地址投递回执，并检查真实邮箱的收件箱、垃圾箱、HTML 与纯文本显示。后台显示 `sent` 只表示 SMTP 接受邮件或管理员确认收到，不保证已进入收件箱。
5. 确认真实收件正常后，再开启每日自动生成与投递。

页面里的 SMTP 就绪判断只检查主机和发件地址等基础条件，不会预先验证密码、网络或实际收件能力。配置完成、协议测试通过和真实收件成功是不同层次的验证。

`EMAIL_RECIPIENTS` 中的有效地址只导入一次，重复地址去重，无效地址数量在页面提示。此后以数据库名单为准，修改环境变量不会持续同步名单；清空或停用名单后重启也不会恢复旧地址。删除收件人不会删除历史投递回执。SMTP 授权码在“邮件设置”中替换或清除，不返回明文。

## 每天定时发送

首次手动验证成功后，在“邮件设置”按目标选择开关（下表保留对应字段名）：

| `DAILY_BRIEFING_ENABLED` | `EMAIL_SCHEDULE_ENABLED` | 行为 |
| --- | --- | --- |
| `false` | `false` | 手动生成、确认和发送 |
| `false` | `true` | 到点发送当日已人工确认的最新版本；无已确认版本就不发送 |
| `true` | `false` | 自动执行每日采集、生成、质量检查与确认，不自动发送 |
| `true` | `true` | 自动执行每日流程，并投递质量检查通过的日报 |

完整自动日报在页面打开两个开关，设置时间与时区即可。仅在尚未保存页面配置时，等价环境配置为：

```dotenv
DAILY_BRIEFING_ENABLED=true
EMAIL_SCHEDULE_ENABLED=true
EMAIL_SEND_TIME=08:00
BRIEFING_TIMEZONE=Asia/Shanghai
```

配置生效后，系统在设定时间开始专用采集、分析与生成，邮件到达时间还包含这些步骤和 SMTP 的耗时。启动时已过设定时间，会补执行当天任务，不补发之前日期。`SCHEDULER_ENABLED` 控制普通周期采集，不替代上述两个开关；连续观测和趋势所需的采集安排见[部署指南](deployment.md)。设置过 `SCHEDULER_UNTIL` 时，确认截止时间尚未到达，否则不再创建自动采集／日报任务。

自动日报只确认质量检查通过的版本；来源部分失败、待审核候选等警告仍展示在正文中，质量阻断、生成失败或不满足当天数据新鲜度要求时不自动发送。缺少发件配置或启用收件人时，日报仍可存档，任务可停留在 `awaiting_email`。

每天开始投递时固定版本和启用名单，重试或重启不会扩大名单，也不因后续出现草稿而自动改发其他版本。新增地址参加下一次日报；需要当天补发时，在日报页面勾选新地址手动发送。停用、删除或修改地址后，尚未发出的旧地址会跳过，已交给 SMTP 的邮件无法撤回。逐地址独立发送，不向收件人暴露其他人的地址。

## 失败排查与日志

| 现象 | 优先检查 |
| --- | --- |
| 发送按钮不可用或提示未配置 | `SMTP_HOST`、合法的 `EMAIL_FROM`、启用收件人、日报确认状态；配置来源是否为数据库；仅部署环境变更需要重建容器 |
| 连接超时或失败 | 主机名、DNS、出站端口、防火墙、服务器到邮件服务的连通性 |
| SSL／STARTTLS 错误 | 端口与加密方式是否匹配、服务商是否支持该方式、系统时间和证书信任；不要通过关闭证书验证绕过 |
| 保存失败或无法解密 | 检查 `EMAIL_SETTINGS_KEY` 是否为有效 Fernet 密钥；更换密钥后需恢复原值或重新保存授权码 |
| 认证失败 | 是否已开启 SMTP、是否使用有效授权码、账号是否正确、是否需要 OAuth2 或被服务商风控 |
| 发件人或收件人被拒绝 | 发件地址权限、收件地址拼写、服务商配额与频率限制，结合回执中的 SMTP 状态码判断 |
| 到点没有自动发送 | 两个开关、时区、截止时间、当日版本及质量状态、每日任务状态、启用名单；采集仍在执行时也不会立即发出 |
| `sent` 但未看到邮件 | 垃圾箱、服务商投递延迟、过滤规则和退信；SMTP 接受不等于最终送达 |
| `unknown` | 可能在提交正文后断线或进程中断；先核实收件箱，再由管理员标记已收到或未收到，避免重复发送 |

每个“日报版本＋收件人”有唯一投递记录和 Message-ID。明确失败按 `EMAIL_MAX_ATTEMPTS` 限制尝试，定时重试有退避；已成功的地址跳过。`unknown` 不自动重试，不能简单把它当作发送失败。

先查后台“收件人管理”的逐地址回执、每日任务状态及错误类型，再查看容器和按天保存的日志：

```bash
docker compose logs --tail=100 backend
docker compose cp backend:/app/logs ./trial-logs
```

按天日志沿用部署时区分文件，页面时区用于日报和发送调度。任务审计和一天试运行导出见[部署指南](deployment.md#一天试运行)。排查时不要公开环境文件或授权码。

## 验证范围

Mailpit 用于本地查看邮件内容及验证 SMTP、重试和去重，不会向真实邮箱中继；操作见[本地隔离验证](deployment.md#本地隔离验证)。已有验证证据见[邮箱管理验收](../reports/email-management-acceptance-v0.1.md)与[Docker 验收](../reports/docker-acceptance-v0.1.md)。服务器真实邮箱收件及连续一天定时投递仍需部署后验收，本文配置示例不代表已完成外部投递测试。
