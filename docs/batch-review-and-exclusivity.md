# 批量归并与互斥审核

[返回项目首页](../README.md) · [跨轮审核身份](review-relation-identity.md) · [采集窗口与事件归并](collection-windows-and-merging.md)

## 使用方法

在“人工复核”页，每条待审核项会直接显示归并目标、加入批量归并的复选框，以及与它互斥的审核编号和目标名称。无需展开原始JSON判断归属关系。

逐条核对后勾选，点击“确认归并所选”。每条归入它自己展示的候选目标，不会把所选话题全部归入某一个目标。“选择本页无互斥项”会跳过所有存在其他目标候选的项，避免替用户擅自选择；“清空选择”可重新选择。本次最多提交100条，页面每页展示50条，可上一页／下一页切换并保留选择，互斥提示也会检查其他页的待审核项。执行期间禁用翻页与选择。

选择“X归入A”后，“X归入B”会禁用并提示对应的已选审核编号。取消前者后才能改选后者。没有目标、目标失效、已处理，或者证据已归属于其他事件的项不能加入批量归并，但原有忽略、拒绝关联等单条处理仍可使用。

执行时页面显示“正在保存并统一重算”，完成后展示逐项结果与更新草稿编号。本版为同步批量请求，没有后台百分比任务。网络中断后先刷新审核列表核实状态，不要依据页面仍在等待就重复提交。

## 归属与互斥规则

单条采集记录仍只允许归属一个事件，不改变数据库的`Item.event_id`约束。不同轮次的采集记录可以归入同一个稳定事件，保留各轮观测。

以下任一依据成立时，将两条审核视为同一线索：采集记录ID重叠、轮次信号ID重叠、来源信号ID重叠，或稳定来源身份重叠。稳定身份沿用知乎问题ID、官媒规范化URL、微博规范化话题标题；微博话题身份继续受24小时范围约束，不能把所有日期的同名话题永久绑定。同一条确切记录的归属限制不受24小时放宽。

- 同一线索、不同目标：互斥，不能同时提交。
- 同一线索、相同目标：可以一起提交；保留审核记录，不因批量而重复创建事件。
- 不同线索、相同目标：可以一起提交。
- 仅标题相似，没有稳定身份或记录重叠：不据此认定互斥，也不自动认定同一事件。

跨轮归属还会核查已接纳的发现记录：同一稳定话题在适用时间内已经归入A时，不能把新轮记录归入B。搜索增强样本和仅审计样本不用于推导新的话题归属；记录本身的已有归属仍会检查。身份或时间信息不足时，按现有身份规则保守处理，无法承诺识别所有同义改名。

本功能不自动合并目标A、B。X分别与A、B相似并不证明A、B是同一事件；事件库中已有的重复事件需要另行确认处理。

## 后端执行与恢复

批量接口为`POST /ops/human-review/batch-merge`，复用管理员鉴权。输入包括审核ID、界面展示的预期目标ID和可选处理理由；后端以数据库中的目标为准，并检查目标是否发生变化。

1. 取得与采集分析共用的运行锁，避免采集、单条审核与批量审核并行修改。
2. 整批预检：重复ID、任务状态、目标有效性、证据已有归属，以及所选项的互斥关系。
3. 预检失败时整批不执行归并，返回冲突编号和原因；不会按提交顺序先到先得。
4. 预检通过后逐条保存审核决定、引用和证据归属。若处理过程中出现单项失败，保留已成功项，明确报告失败项；不宣称整个批次为原子事务。
5. 将成功项涉及的事件合并处理，每个采集轮次只读取和回放一次，然后统一更新分类、趋势和简报。保留原始观测时间、原有窗口与旧简报版本，只新增一份更新草稿。

单条“确认归并”也使用同一归属预检，不能通过直接调用旧接口绕过跨轮归属限制。

统一重算失败时，审核决定仍保存，队列显示可重试项。点击该批任意一项的“重试分类与日报更新”，会重新处理整批成功归并的事件，并同步更新该批重算状态，不再次执行归并。重算阶段开始前已保存批次成员，便于恢复该阶段的失败。归并过程中突然终止时可能只完成部分审核，应刷新列表核实，不保证整批回滚。

不新增CLI调用、不重新采集、不发送邮件；本功能不调整语义模型、阈值或人工确认的判定精度。提速来自减少重复的历史扫描和简报重建，实际耗时仍取决于历史轮次和事件数量。
