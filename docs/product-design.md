# 产品与展示设计

[返回项目首页](../README.md) · [工作流](architecture.md) · [MVP 操作指南](user-guide.md)

本文说明每日简报的展示结构、管理功能和产品边界。详细字段以[数据契约](data-contracts.md)为准。

## 产品目标与范围

每天回答两个问题：过去 24 小时，知乎、微博和官媒各自关注哪些事件？这些事件有哪些跨平台共同关注和官媒报道依据？

当前交付的是模式 A：每日热点简报。它将采集结果汇总为带证据的事件卡片，生成固定版本，供网页、JSON 导出和 HTML／纯文本邮件共用。长图是可选的后续导出形式，当前图片工具尚未实现。

模式 B：用户指定事件后检索已有证据，仍是占位入口。未来可复用事件、来源、匹配与评分能力；当前没有完整的问答、RAG 或用户主题订阅功能。

## 简报的两个视角

| 视角 | 展示内容 | 数据依据 |
| --- | --- | --- |
| 平台栏目 | 知乎关注、微博关注、官媒报道 | 当前分析窗口内，同一事件已接纳的来源证据 |
| A–F 分类栏目 | 双社区共同关注、单社区关注、官媒支撑等组合 | 已融合事件的 `platform_presence`、跨平台匹配方式与官媒支撑状态 |

两个视角共用稳定 `event_id`。同一事件可以出现在知乎和微博两个栏目里，在某个分类栏目内只出现一次。它们不是两轮独立抽取，也不为了填满 A/B/C 等类别而强行合并。

当前日报的分类栏目按标题和事件 ID 做稳定排序，不计算跨平台总分。平台栏目先区分当前在榜／未知／离榜，知乎可比较真实榜位，微博比较本平台分数；官媒按引用来源数和报道时间排序。完整规则见[分类与组装](hotspot-classification.md)。

## 时间口径

- 所有栏目使用同一轮次固定的 UTC `(window_end - 24h, window_end]`，默认以北京时间展示。
- 社区话题按真实榜单观测入窗；旧问题今天重新上榜，仍属于今天的关注。
- 官媒按可靠的报道发布时间入窗，旧报道重新抓取不能成为当天新热点。无有效时间的记录保留审计，不作为当天发现依据。
- 当前离榜与过去 24 小时被关注是两件事：离榜事件在窗口内仍可展示，最后有效发现证据过期后退出当前结果。
- 来源失败、残缺榜单、历史不足或采样口径变化时显示未知或“趋势待确认”，不补造数据。

详见[热度与趋势](platform-heat.md#滚动窗口与入榜离榜)。

## 事件卡片

| 信息 | 主要字段 | 用户应如何理解 |
| --- | --- | --- |
| 稳定身份与文字 | `event_id`、`title`、`summary` | 同一事件跨轮次追踪，摘要由当前规则与模板生成 |
| 来源覆盖 | `platform_presence`、`cross_platform_match_type` | 哪些平台的哪些通道提供了已接纳证据 |
| 分类与支撑 | `priority_category`、`official_support_status`、`confidence_level` | 类别及证据完整程度，不是事实真伪保证 |
| 平台状态 | `platform_heat_analysis.platforms` | 各平台是否在榜、静态分、连续观测时间和趋势 |
| 依据与限制 | `source_citations`、`evidence_summary`、`quality_flags`、`risk_notes` | 点击原始来源、检查缺失和保守表述 |

微博 RSS 顺序只说明样本中的位置。没有可用 CLI 增强时，可以展示微博话题出现及持续观测，不能据此声称互动热度正在上升。官媒报道数量只用于描述覆盖，不转成公众讨论量。

## 管理后台

| 页面 | 当前功能 |
| --- | --- |
| 简报与历史 | 手动采集、预览固定版本、质量结果、确认版本、指定收件人发送及导出 |
| 运行与用量 | 来源健康、采集任务、HTTP／CLI 实际调用、耗时、失败类型和可获取的额度信息 |
| 人工复核 | 对比候选与目标事件，查看实体／动作／时间等匹配证据，归并、单独建事件、忽略或拒绝 |
| 邮件管理 | 收件地址及备注增删改、启停、最近回执、每日任务和投递状态 |

当前是单管理员后台，使用管理员令牌与会话 cookie，不是面向公众的邮箱自助订阅系统。SMTP 发件服务和定时配置在环境文件维护；收件人名单在数据库维护，修改即时生效。

## 发布与修正

一轮分析之后执行“生成 → 质量检查 → 保存”，页面与邮件读取同一个已保存版本。手动发送必须先确认；开启自动日报时，专用每日任务可自动确认质量通过的版本。阻断版本不发送，来源部分失败等警告随正文保留。

人工复核只改变已确认的事件关系。系统按原始观测时间重算并生成更正草稿，已有版本的内容保持不变。单平台热点的分类置信度较低，不等于它是待确认的合并关系；已接纳的 E 类仍可展示。

邮件按“版本＋收件人”去重，定时批次固定当日名单；新增邮箱默认参加下一次，可手动补发当天版本。具体发送、失败重试和未知回执处理见[MVP 使用指南](user-guide.md#邮件配置与发送)。

## 当前边界与后续工作

已经接通的是规则抽取、事件融合、分平台分析、日报与后台操作。仍需服务器连续 24 小时实采及真实邮箱收件验收；历史一次请求成功不代表长期可用。

LLM 抽取 refinement、长图渲染、Mode B、自动业务数据清理和大规模负载验证仍未完成。实现范围与实际验证分开记录，见[验证记录](../README.md#验证记录)。
