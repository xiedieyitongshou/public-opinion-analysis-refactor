# 人工复核与简报关联

[返回 README](../README.md)

## 如何使用

- 在简报卡片或预览中点击“复核本期”，进入该简报的待处理列表。
- 人工复核页顶部可以切换简报，默认选择最新一期。列表、数量、分页都按所选简报计算。
- 任务卡片显示所属简报；“查看所选简报”可以返回预览。
- 单条审核、批量归并和重算重试都携带当前简报上下文，只为该期生成更正版。原来的历史正文保留。
- 批量勾选可以跨页保留，切换简报会清空勾选和输入理由。批量提交期间不能切换范围。
- 还未生成简报、缺少来源标识的旧任务放在“尚未关联简报的任务”，不会按标题或日期猜测归属。

## 关联口径

这是一份复核关系与简报的多对多关联，不是复制复核任务：

1. 通过 `ReportRevision.run_id` 识别简报所属分析任务，旧数据兼容正文中保存的 `run_id`。
2. 汇总简报展开 `report_window.run_ids`，包含真正组成该期的采集轮次；兼容旧夜间汇总的任务前缀。
3. 复核任务的 `payload.run_id`、跨轮去重后的 `payload.run_ids` 与上述集合有交集，即属于该简报。旧任务缺少这两个字段时，尝试使用其原始 `agent_task_id` 对应的采集任务标识。
4. 同一关系在多轮重复出现，仍保留一个审核任务，可以同时出现在单轮简报和包含这些轮次的汇总简报中。处理一次后，它的关联视图会同步反映已处理状态。
5. 新旧更正版共用同一期的关联范围；界面会跟随本期的新版本，不跳到无关的最新一期。

因此各单轮简报的待审数量不能简单相加：同一关系在两轮各出现一次，汇总简报仍只计一条。

审核决定修改的是既有的事件归属关系，并非给每份简报维护一套相互冲突的归属。当前操作只重建所选一期；其他历史正文不会自动改写。互斥关系仍在全局检查，不会因为筛选了简报而解除“同一线索只归属一个事件”的限制。

简报正文的待审数量是在生成时保存的快照；卡片与复核页数量表示当前状态。审核后查看新版本可看到更新后的正文与数量。

后续成功结果覆盖旧技术异常时，相关任务自动退出该期的待审队列；原错误与恢复依据保留。具体条件见[技术异常复核的自动收尾](technical-review-recovery.md)。

## 后端约束与兼容

- `GET /api/review-queue?report_id=...`：先按简报筛选，再计数、分页；包含本期已审核但重算失败的任务。
- `GET /api/review-queue?unbound=true`：显示没有任何已生成简报关联的任务。
- 旧版不传筛选参数的查询保留全局行为，前端默认使用按简报查询。
- 单条决策和批量归并支持 `report_id`；后端在修改归属之前核对所选任务是否属于该简报，混入其他期会拒绝执行。
- 重算失败或进程中断前，保存 `requested_report_id`；重试保持原简报上下文。
- 旧调用没有显式指定简报时，选择最近的**相关**简报，避免修改无关的全局最新一期。没有可追溯来源时不随意更新其他简报。
- 重算沿用该期保存的规则／LLM模式，使用已有采集数据，不重新采集或发邮件。

无需数据库迁移或重新采集。关联复用现有来源记录，规则模式和LLM模式共用。
