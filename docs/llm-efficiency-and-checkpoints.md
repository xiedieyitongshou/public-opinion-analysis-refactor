# LLM增量分析、预算与断点管理

## 修改方案与记录（2026-11-01）

在`EVENT_REASONING_MODE=llm`中增加下列措施，保留引用及Schema校验，不将BM25、embedding分数混进LLM归并结论。

1. 精确来源身份先定位归属：使用来源限定ID、知乎问题ID、具体URL及既有来源记录。通用首页不算唯一URL，路径和查询参数大小写保留；多个目标竞争继续送审。归属复用不跳过每轮热度、转评赞和新正文更新。
2. BM25与embedding分别召回、融合排名，普通候选默认最多20个，小池直接完整比较。检索范围、选中与排除ID写审计；embedding不可用时明确技术异常，不隐性扩大到全部候选或用旧分数自动合并。
3. 抽取缓存依据正文及相关发布时间，来源ID可逆重绑；观测时间和热度变化不重新抽取，含相对日期的材料按参考日期隔离。逐对缓存包含双方完整材料、相关时间、模型、提示词和Schema版本。只有通过校验的判断可缓存，新正文／新报道正常进入比较。
4. 缓存未命中组合按原批大小打包，最多两个请求并发。所有分支共享调用预算，线程保留请求上下文，数据库归属仍顺序修改。一个批次失败不会丢弃其他批次的有效缓存，但未核对的竞争目标仍阻止自动归并。
5. 官媒继续复用query、搜索缓存和时间过滤，先核对已采报道，未找到且预算允许时查询官网。新事件查旧报道，新报道也与旧事件核对；不假设官媒一定先报道。已检查的相同组合复用，负结果只对已检查材料有效。
6. 抽取、归并及分类按已完成项保存检查点。进程终止或预算耗尽保留采集、已完成归属、评分及阶段输出。不会把未完成变成“不相关／无官媒报道”；历史简报重建只读LLM缓存，已接纳的当前窗口官媒关联保留。
7. 原提示词加固保留，所有实际HTTP响应的usage在结果校验前记账，失败也计入。`llm_usage`日志及后台任务区显示已报告token、预算占用和调用数，旧任务缺记录不补记为0。

## 配置

```dotenv
EVENT_REASONING_MODE=llm
LLM_RETRIEVAL_ENABLED=true
LLM_RETRIEVAL_USE_EMBEDDING=true
LLM_CANDIDATE_LIMIT=20
LLM_CANDIDATES_PER_REQUEST=4
LLM_MAX_CONCURRENT_REQUESTS=2
LLM_TOKEN_BUDGET_PER_RUN=500000
LLM_MAX_CALLS_PER_RUN=100
LLM_CACHE_HOURS=24
```

调用次数上限沿用现有配置，Docker环境若显式配置更高值，以该值为准；token预算默认每轮50万。`REQUEST_LIMITS`中显式的deepseek上限也会约束请求。预算请求前保守预留（包括在途请求），usage缺失时保留预留；provider报告齐全后按实际tokens结算。进程中止后的未知使用量不会自动退回，需核对账单后再决定是否明确提高预算。预算累计跨同run_id续跑，不因客户端重建而清零；多轮会话的各run分别计账，尚无会话级自动预算分配。

缓存不命中时`LLM_RETRIEVAL_ENABLED=false`可显式改回全量候选，`LLM_MAX_CONCURRENT_REQUESTS=1`可串行对照；原规则模式继续使用其原有召回与模型缓存。LLM模式新增embedding会增加本地内存与初始化耗时，只加载embedding，不加载reranker。

## 续跑与界面

任务历史中断行可点击“继续分析（复用采集）”；对应管理员接口为`POST /api/jobs/{run_id}/resume`。只允许已保存采集数据的中断LLM任务，无活动任务时排队。普通语义待审核不属于断点续跑，预算已耗尽需明确调整配置后才可继续。若同一来源已被后续轮次更新，拒绝旧窗口在原库续跑，使用隔离历史回放，避免覆盖新观测。人工归属或事件材料变化会使相关检查点失效。

`GET /api/jobs/{run_id}/llm-usage`查询本轮分任务调用、已报告token、保守占用及上限；页面任务区实时展示。接口沿用管理员鉴权，不返回Key、完整原文或供应商鉴权头。

## 运行边界

来源采集阶段以已保存的完整阶段结果复用，尚不支持从某一条未完成的CLI相关性判断开始恢复；抽取、归并和分类有逐项断点。每轮预算是保守上限，不能保证所有冷启动工作在50万tokens内完成，达到上限时需查看占用与检查点后决定是否调整。多轮会话目前分别计账，尚无会话级自动预算分配。

冷调用不保证节省；缓存只复用已经校验且材料、模型、提示词版本相同的结果。候选上限约束交给LLM的集合，不代表整个检索池停止增长。正文、相关时间、来源归属或版本变化会使相应缓存或检查点失效。

## 断点兼容修复（2026-11-02）

- 阶段完成时保留逐项完成ID、来源归属和材料版本，不再覆盖这些元数据。
- 只有标记为完整的阶段输出才能整体复用；部分完成阶段进入逐项恢复，避免漏掉未处理条目。
- 恢复时先剥离内部 `_checkpoint` 元数据，再进行业务Schema校验，防止额外字段导致失败。
- 人工归属或事件材料变化后重新核对检查点，不信任已过期的归并结论。
- 官媒 F 类与社区链路分离后更新断点版本，旧版完成输出不能直接跨版本复用。

回归覆盖预算停止、阶段续跑、来源归属变化及旧格式检查点。具体实验脚本、用量与回放报告保存在本机私有目录，不随代码发布；历史样本回放不能替代长期运行和语义质量验收。
